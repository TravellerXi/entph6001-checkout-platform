# Cloud-Native Checkout Platform — ENTPH6001 Supplemental Assignment

A K3s implementation of a small e-commerce checkout platform with enforced trust tiers,
tested degradation behaviour, request correlation, and verified security posture.

## What this is

The organisation's existing checkout runs as a loose set of containers. This repository proposes
and implements a cloud-native replacement in which service boundaries, the request path, trust
tiers, configuration/secret handling and failure behaviour are explicit and — crucially — testable.

```text
Client → Traefik Ingress → gateway (public)
                              → checkout-fn (internal)
                                   ├→ pricing-fn   (internal, critical dependency)
                                   └→ inventory-fn (internal, non-critical)
                                          └→ postgres (protected, PVC)
```

## Repository layout

```text
k8s/          Kubernetes manifests, applied in numeric order
services/     Three Node.js services (source + multi-stage Dockerfiles)
scripts/      Deployment and evidence-producing test scripts
evidence/     Captured output from real runs (referenced by the report appendices)
```

## Prerequisites

- Ubuntu 24.04 host with 2 vCPU / 4 GB RAM / 10 GB disk (per Lab 3.2)
- K3s: `curl -sfL https://get.k3s.io | sh -`
- kubeconfig readable by your user: `~/.kube/config`, mode 600
- Docker, for building images only: `bash scripts/00-install-docker.sh`

## Deploy

```bash
bash scripts/deploy-all.sh
bash scripts/30-smoke-test.sh
```

The gateway is intentionally **not** published to the internet. Reach it through a tunnel:

```bash
ssh -L 8080:localhost:80 student@<host>    # then browse http://localhost:8080
```

## Security notes

- No real credentials are committed. `k8s/11-secret.example.yaml` is a template; the live Secret is
  generated by `scripts/20-create-secret.sh` and never written to disk or to this repository.
- Evidence logs are scrubbed of secret material by design — `80-security-audit.sh` reports that the
  Secret is retrievable without printing its value.
- Namespace `shop` enforces the `restricted` Pod Security Standard. All containers run non-root with
  all capabilities dropped, no privilege escalation, and no service-account token mounted.
- Known residual risks are listed and prioritised in Section 4 of the report.
